# Маркетинг проектов и привлечение клиентов

Маркетинг каждого проекта — это серия тестов спроса. У каждого теста свой бюджет, его одобряет директор. Деньгами управляет сервер, а не агенты: бюджет, стоп-правила, срок и режим «СТОП» исполняются в коде.

## Как идёт тест

1. **План.** Директор по маркетингу (Мария) готовит план через `mk_propose_test`:
   - сегмент: кто, страна, язык;
   - оффер и цена;
   - 1–4 канала с бюджетом на каждый;
   - срок 3–60 дней, обычно 14;
   - порог успеха: цена заявки, конверсия, цена клиента, число заявок или покупок;
   - стоп-правила.
2. **Ваше решение.** План приходит в Telegram с кнопками «Одобрить бюджет / Отклонить». Он также виден во вкладке «Маркетинг» в пульте и на плакате «Маркетинг» в кабинете.
3. **Подготовка.**
   - Тексты пишет Никита, креативы делает Вера, лендинг собирает IT.
   - На лендинг ставится счётчик, его код — в задаче и в карточке теста.
   - Для постов, писем и переписки агенты делают короткие ссылки с метками (`mk_link`).
4. **Запуск.** Егор создаёт кампании через `mk_campaign`. Кампания создаётся **выключенной**; включается после проверки. При включении сервер проверяет: включённые кампании × оставшиеся дни ≤ остаток бюджета канала и теста.
5. **Каждый день.**
   - Каждые 3 часа сервер забирает цифры из кабинетов Meta и Google: показы, клики, расход.
   - Ручные цифры каналов без API (переписка, сообщества) агенты вносят через `mk_log`.
   - Расход рекламы попадает в учёт, категория `ads`.
   - Сервер сам ставит на паузу кампанию с CTR ниже порога после 1000 показов и канал без заявок на половине своего бюджета.
   - В 10:00 таргетолог получает задачу на проверку.
6. **Половина срока.** Промежуточный итог. Если заявок нет, меняют оффер или аудиторию, а не бюджет.
7. **Конец теста.** Тест завершается по сроку, по исчерпании 95% бюджета или кнопкой «Остановить». Сервер выключает всю рекламу теста и ставит задачу на отчёт.
8. **Отчёт.** `mk_report` присылает вам карточку:
   - потрачено, визиты, заявки, покупки, цена заявки и клиента по каналам;
   - пороги ✅/❌;
   - выводы команды и рекомендация.

   Кнопки: «🚀 Масштабировать», «🔁 Ещё тест», «✖ Закрыть направление». Первые две ставят задачу маркетингу на следующий план.

## Воронка и откуда цифры

| Шаг | Источник |
|---|---|
| Показы, клики, расход | API Meta / Google, для остальных — `mk_log` или ручной ввод в пульте |
| Переходы по коротким ссылкам | `/go/<код>` — считает сервер |
| Визиты, заявки | Счётчик `t.js` на лендинге. Визит считается раз в день на посетителя, заявка — раз на посетителя |
| Начало оплаты | Клик по кнопке Stripe на лендинге |
| Покупка | Только вебхук Stripe с подписью: кнопка получает `client_reference_id`, и оплата привязывается к каналу первого визита |

Код счётчика для лендинга (ключ теста — в карточке):

```html
<script src="https://ВАШ-ДОМЕН/t.js" data-test="kXXXXXXXXXX" defer></script>
<form data-neiro="lead">…</form>   <!-- отправка формы = заявка -->
```

Счётчик не использует cookies и не собирает личные данные: только случайный идентификатор посетителя в localStorage и метки канала. Политика конфиденциальности на лендинге всё равно нужна.

## Подключение кабинетов (один раз, делает человек)

Ключи кладутся только в `deploy/.env` на сервере, список — в `deploy/.env.example`.

### Meta (Facebook и Instagram Ads)
1. Business Manager: рекламный аккаунт, страница компании, способ оплаты — виртуальная карта Revolut с месячным лимитом.
2. Системный пользователь с доступом к аккаунту и странице, токен с правом `ads_management`.
3. В `.env`: `META_ACCESS_TOKEN`, `META_AD_ACCOUNT_ID=act_…`, `META_PAGE_ID`, `META_CURRENCY`.

Кампания создаётся с целью «Трафик» и показывается по странам и возрасту. Набор объявлений получает дату окончания теста, так что сама площадка тоже остановит показы.

### Google Ads (поиск)
1. Аккаунт Google Ads и управляющий аккаунт (MCC). Developer token с уровнем доступа Basic или выше; заявку одобряет Google.
2. OAuth-клиент в Google Cloud и refresh token пользователя с доступом к аккаунту.
3. В `.env`: `GOOGLE_ADS_DEVELOPER_TOKEN`, `GOOGLE_ADS_CLIENT_ID`, `GOOGLE_ADS_CLIENT_SECRET`, `GOOGLE_ADS_REFRESH_TOKEN`, `GOOGLE_ADS_CUSTOMER_ID`, при MCC — `GOOGLE_ADS_LOGIN_CUSTOMER_ID`.

Создаётся поисковая кампания со стратегией «Максимум кликов», ключевыми словами (фразовое соответствие) и адаптивным объявлением.

**Версии API меняются.** Перед запуском сверьте `GOOGLE_ADS_API_VERSION` и `META_API_VERSION` с актуальными версиями в документации площадок и проведите тест на 5 €.

### Соцсети
- **Telegram-канал** — `TELEGRAM_CHANNEL_ID`, бот должен быть администратором канала.
- **Instagram** — профессиональный аккаунт, связанный со страницей Facebook: `IG_USER_ID`, `IG_ACCESS_TOKEN`. Публикует только с картинкой: нужна публичная ссылка на JPG.
- **LinkedIn** — страница компании, токен с правом публикации от имени организации: `LINKEDIN_ACCESS_TOKEN`, `LINKEDIN_ORG_URN`.

Посты идут через действие `post_social` и общий лимит внешних сообщений в сутки. Посты в сообществах и на форумах сервер не публикует: агент готовит текст, человек публикует от своего имени.

### Каналы без API
TikTok, LinkedIn Ads, Яндекс Директ:
- агент сохраняет спецификацию кампании, вам приходит сообщение «запустить вручную»;
- после запуска нажмите «Я запустил» в карточке теста;
- цифры вносятся вручную.

Для пауз таких кампаний сервер присылает напоминание: выключить их через API он не может.

## Защиты

- **Без одобренного теста** кампанию не создать и не включить.
- **Бюджет.**
  - При включении и смене бюджета сервер проверяет, хватает ли остатка канала и теста.
  - При 95% потраченного бюджета вся реклама теста выключается.
  - Площадки могут перерасходовать дневной бюджет в пределах дня: Google — до 2×. От этого защищает месячный лимит рекламной карты.
- **СТОП** (пульт, кабинет, `/stop`) ставит всю включённую рекламу на паузу и не даёт её включить.
- **Сверка банка.** Списания Meta, Google, TikTok, LinkedIn и Яндекса получают статус «счёт рекламы» и не дублируют расход: он уже учтён по цифрам кабинетов. Раз в месяц сравнивайте сумму счетов с расходом `ads` в «Деньгах».
- **Запреты для агентов:**
  - спам и купленные базы;
  - фейковые аккаунты и отзывы;
  - выдавать себя за покупателей.

  Это записано в регламент отдела. Письма уходят только из ящика агента, лимит — не больше 3 получателей без вашего «да».

## Telegram
- `/marketing` — список тестов: этап, потрачено, заявки, цена заявки.
- Кнопки в сообщениях: одобрить или отклонить план, решение по отчёту.

## Что проверено, а что нет
Логика модуля покрыта тестами на поддельных ответах площадок. Живые вызовы Meta, Google Ads, Instagram и LinkedIn ещё не проверялись: нужны ваши кабинеты и ключи. Первый запуск — тест на 5 € с ручной проверкой в кабинете площадки.
