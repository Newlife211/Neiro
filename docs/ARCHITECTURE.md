# Архитектура боевой версии

```
 Директор ──► Пульт (HTTPS, токен) ─┐          ┌─► Claude API (мозг агентов)
          └─► Telegram-бот ─────────┤          │
                                    ▼          │
                 ┌──────────── Сервер Node 22 ─┴───────────────┐
                 │ Очередь задач → Агент → Инструменты         │
                 │                     └─► Политика (лимиты)   │
                 │                          ├ сам (в пределах)  │
                 │                          └ ждёт директора    │
                 │ Исполнители: AgentMail, Telegram, Stripe,   │
                 │   ЮKassa, деплой-хук                        │
                 │ Учёт: доходы, расходы, Claude API, аудит    │
                 │ SQLite (один файл, бэкап каждую ночь)        │
                 └─────────────────────────────────────────────┘
 Stripe / ЮKassa ──► вебхуки (проверка подписи / перепроверка через API) ──► Учёт
```

## Модули (`server/src`)
| Файл | Что делает |
|---|---|
| `config.js` | Все настройки из `.env`. Ключей в коде нет |
| `db.js` | Схема SQLite: агенты, задачи, проекты, действия, учёт, документы, аудит |
| `policy.js` | **Главная защита.** Решает, что агент делает сам, а что ждёт директора |
| `actions.js` | Цепочка действия: предложить → проверить политикой → подтвердить → исполнить → записать в учёт. Защита от дублей |
| `executors.js` | Реальные интеграции: письма, посты, ссылки на оплату, возвраты, деплой |
| `payments.js` | Stripe (Payment Links, подпись вебхуков) и ЮKassa (платежи, перепроверка, чеки 54-ФЗ) |
| `fx.js` | Курсы ЕЦБ и ЦБ РФ, ежедневное обновление |
| `revolut.js` | Revolut Business: OAuth (JWT RS256), виртуальные карты под траты, счета, операции |
| `bank.js` | Импорт выписок Revolut и Paysera, автосверка с учётом, решения директора |
| `llm.js` | Claude Messages API через fetch, повтор при перегрузке, учёт стоимости каждого вызова |
| `agent.js` | Рабочий цикл агента: системный промпт с должностью и регламентом, 7 инструментов, контроль этапов проекта |
| `worker.js` | Очередь: приоритеты, параллельность, повторы, пауза при исчерпании бюджета Claude |
| `company.js` | Решения по проектам, утренний отчёт CDO, вечерние итоги, разбор входящей почты |
| `telegram.js` | Уведомления и кнопки «Одобрить / Отклонить». Команды принимаются только из чата директора |
| `http.js` | API пульта, вебхуки, страница пульта |

## Инструменты агентов
- `create_task` — делегировать коллеге или отделу; дубли и слишком длинные цепочки отсекаются.
- `write_document` и `read_documents` — PRD, исследования, планы, тексты, код.
- `upsert_project` — проекты. Дальше этапа «Решение директора» проект без вашего «да» не уходит.
- `propose_action` — любое действие во внешнем мире, только через политику.
- `remember` — долговременная память агента.
- `company_status` — цифры компании.

## Цепочка ИИ-продукта
R&D находит гипотезу → анализ и ROI → **ваше решение** → продуктовая команда пишет PRD и делает MVP → **деплой с вашим «да»** → маркетинг и продажи → ссылки на оплату Stripe или ЮKassa → оплата приходит на ваш счёт у провайдера → вебхук → «Деньги» в пульте.

## Штат
Состав берётся из симулятора (`server/data/agents.json`, 56 сотрудников). На старте включены 25 человек под SaaS:
- администрация (COO, секретарь, CDO);
- R&D;
- маркетинг;
- продажи;
- поддержка;
- бухгалтерия;
- юристы;
- продуктовая команда ИИ.

Остальных, включая крипто-крыло, директор включает в разделе «Агенты». Каждый включённый агент расходует Claude API.

## Что сознательно оставлено директору
Универсального API для оплаты произвольных счетов нет. Поэтому трата сначала проходит политику: в пределах лимита — сама, сверх лимита — после вашего «да». Затем, если для поставщика нет интеграции, она приходит вам как «выполнить вручную», а после оплаты вы отмечаете её в пульте. Реальной торговли на бирже в этой версии нет. Это отдельный этап после 30+ дней бумажной торговли, см. `docs/crypto-trading.md`.

## Масштабирование
Один сервер с SQLite выдерживает десятки агентов. При росте:
- переход на Postgres (слой `db.js` изолирован);
- отдельные воркеры;
- интеграции с рекламными кабинетами (Supermetrics, API Google/Meta) как новые исполнители.
