# Финансы: курсы, карты под траты, выписки и сверка

## Что работает автоматически
| Что | Как |
|---|---|
| **Курсы валют** | Раз в сутки: ЕЦБ (все валюты к евро) и ЦБ РФ (рубль). Все суммы пересчитываются в базовую валюту по свежему курсу. Если источник недоступен, используется последний известный курс. Ручные `FX_*` в `.env` — только запасной вариант |
| **Карта под каждую трату** | Трата агента одобрена (сама в пределах лимита или вами). Сервер выпускает в Revolut виртуальную карту **ровно на эту сумму**: лимит на одну операцию и на весь срок, карта живёт 14 дней, в метке номер траты. Потратить больше одобренного невозможно |
| **Закрытие трат** | Каждые 15 минут сервер забирает выписки Revolut и Paysera. Списание по карте закрывает трату фактической суммой, записывает расход в учёт и закрывает карту |
| **Сверка** | Каждая операция банка получает объяснение: трата агента, выплата Stripe/ЮKassa (выручка уже учтена по вебхуку), перевод между своими счетами, запись в учёте с той же суммой (±3 дня). Остальное попадает во вкладку **«Сверка»**, и одна сводка приходит в Telegram |
| **Остатки** | Остатки по счетам Revolut и Paysera видны в «Обзоре» и «Сверке» |

Кто нажимает «Оплатить»: номер карты сервер **не читает и не хранит**. Доступ к данным карт (`READ_SENSITIVE_CARD_DATA`) не запрашивается. Картой расплачиваетесь вы из приложения Revolut. Поставщики, которые списывают сами по подписке, получают карту один раз. Это сознательная граница безопасности: ИИ-агент не держит в руках платёжные реквизиты.

## Подключение Revolut Business (~20 минут)
Нужен тариф Revolut Business с доступом к API.
1. На сервере сгенерируйте ключ и сертификат:
   ```bash
   mkdir -p /opt/neiro/deploy/secrets && cd /opt/neiro/deploy/secrets
   openssl genrsa -out revolut.pem 2048
   openssl req -new -x509 -key revolut.pem -out revolut-public.cer -days 1825 -subj "/CN=neurosfera"
   chmod 600 revolut.pem
   ```
2. В Revolut Business откройте **Settings → APIs → Business API → Add API certificate**:
   - загрузите содержимое `revolut-public.cer`;
   - в поле OAuth redirect URI укажите `https://ВАШ-ДОМЕН/`;
   - сохраните **Client ID**.
3. В `deploy/.env` впишите:
   - `REVOLUT_CLIENT_ID`;
   - `REVOLUT_JWT_ISS=ВАШ-ДОМЕН` (без https и слеша);
   - `REVOLUT_CARD_CURRENCY` — основная валюта бизнеса.
4. В той же карточке API нажмите **Enable access** и подтвердите. Revolut перенаправит на `https://ВАШ-ДОМЕН/?code=...`. Скопируйте значение `code` и выполните:
   ```bash
   cd /opt/neiro/deploy && docker compose run --rm app node src/tools/revolut-auth.js КОД
   ```
   Полученную строку `REVOLUT_REFRESH_TOKEN=...` впишите в `.env` и выполните `docker compose up -d`.
5. Чтобы выпускать карты через API, Revolut требует включить Cards API: напишите на api-requests@revolut.com. Пока его нет, выписки и сверка уже работают, а траты приходят вам «вручную».
6. Чтобы видеть карты в своём приложении, укажите свой ID участника команды в `REVOLUT_CARD_CONTACT_IDS` (Settings → Team).

Совет: заведите в Revolut отдельный субсчёт «Агенты» с ограниченной суммой и укажите его ID в `REVOLUT_CARD_ACCOUNT_IDS`: карты будут списывать только с него. Даже при сбое потеряете не больше остатка на нём.

## Подключение Paysera (выписки, только чтение)
1. В Paysera создайте **персональный токен доступа** только с правом чтения выписок и остатков (`statements:read`, баланс). Права на переводы не давайте.
2. В `.env`: `PAYSERA_TOKEN=...`, `PAYSERA_ACCOUNT=EVP...`.

## Проверка
Во вкладке «Сверка» нажмите **«Обновить сейчас»**. Появятся остатки, курсы и операции за последние 30 дней.

## Ограничения этой версии
- **Переводы по реквизитам (IBAN)** агентам не доступны. Это главный канал мошенничества: поддельный счёт в письме может подменить реквизиты. Платежи по счетам проводите вы сами, а сверка их распознает.
- **Формат выписки Paysera** собран по документации. Первую выгрузку стоит сверить глазами с личным кабинетом.
- **Комиссии банков и Stripe** пока учитываются только через «Сверку» (запись расхода с категорией `bank_fees`).
